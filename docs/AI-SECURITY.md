# AI Security Architecture

## Overview
CAREGRAPH utilizes LLMs for document summarization, medical term extraction, and timeline generation. Security around AI integrations in healthcare is critical to prevent data leaks and prompt injection.

## Current Architecture
In the current demo setup, no actual AI API calls are made from the browser. The system simulates AI responses to demonstrate the user experience without requiring backend infrastructure or risking data exposure.

## Production Architecture (Browser → Backend → AI Provider)
In a production environment, the architecture must strictly enforce that the frontend NEVER talks directly to the AI provider (e.g., OpenAI, Anthropic).
1. Frontend requests a summary from the Backend.
2. Backend verifies user authorization and access grants.
3. Backend retrieves the necessary patient data.
4. Backend securely constructs the prompt, masking PII if required.
5. Backend calls the AI Provider API using a securely stored backend API key.
6. Backend sanitizes the output and returns it to the Frontend.

## Why API Keys Must NEVER Be in Frontend `VITE_` Variables
Any environment variable prefixed with `VITE_` is statically injected into the frontend JavaScript bundle. 
- If an OpenAI key is placed in `VITE_OPENAI_API_KEY`, anyone can open Chrome DevTools, extract the key, and incur massive usage bills on your account.
- **Rule**: All third-party service keys belong strictly on the server.

## Prompt Injection Prevention
When integrating LLMs, user-supplied text (e.g., a patient's uploaded document) must be treated as untrusted.
- Use strict system prompts.
- Utilize delimiters to separate instructions from user data.
- Avoid passing raw user input directly into executable contexts.

## Model Output Sanitization
AI output can hallucinate or generate unsafe content.
- Ensure all AI-generated content rendered in the browser is properly escaped to prevent Cross-Site Scripting (XSS).
- Validate that the AI response matches the expected JSON schema before persisting it to the database.

## AI-Generated Content Labeling
All AI-generated summaries, extracted conditions, or insights must be clearly labeled with a disclaimer (e.g., "Generated by AI - Verify before clinical use").

## Human-in-the-Loop for Clinical Decisions
AI is a co-pilot, not an autopilot.
- Any extracted data (e.g., a new medication found in an uploaded PDF) must be explicitly reviewed and approved by a Doctor or Patient before becoming part of the official medical record.
- The system must never make automated clinical or diagnostic decisions based solely on AI output.

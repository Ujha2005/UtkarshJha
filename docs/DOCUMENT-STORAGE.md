## 1. Document Lifecycle Pipeline

The lifecycle of an ingested medical document transitions through seven formal phases:

```
[1. Upload]
    │  • Client file selection (PDF, TXT, JSON, Scanned Image)
    │  • Client-side validation: MIME type, size limit (< 25 MB)
    ▼
[2. Secure Ingestion & Quarantine]
    │  • Stream to secure quarantine bucket (AWS S3 / GCS)
    │  • Antivirus scanning (ClamAV)
    │  • Compute SHA-256 cryptographic digest for integrity verification
    ▼
[3. Extraction & Metadata Indexing]
    │  • Document metadata created in database
    │  • Multi-engine extraction: OCR (Tesseract / Textract) + Clinical NLP (Gemini / Med-PaLM)
    ▼
[4. Candidate Entity Generation]
    │  • Extracted entities: lab results, diagnoses, medications, procedures
    │  • Confidence scoring (0.0 to 1.0)
    │  • Automated duplicate detection & clinical conflict detection
    ▼
[5. Human Review Workflow (HITL)]
    │  • Clinician / patient interactive reconciliation
    │  • Actions per candidate: Accept, Edit (userEdited flag), Reject
    ▼
[6. Clinical Record Commit]
    │  • Accepted entities committed into primary longitudinal store
    │  • Automatically appends to Lab Trends, Medications list, Timeline events
    │  • Generates formal sourced DiagnosticReport
    ▼
[7. Provenance & Audit Ledger]
    │  • Every entity retains `sourceDocumentId` and timestamped origin
    │  • Event logged to immutable audit trail: DOCUMENT_COMMIT
```

## 2. Storage Provider Interfaces [IMPLEMENTED]

`src/services/documentStorage.ts` formalizes the storage boundary:

```ts
export interface StoredDocumentMetadata {
  id: string;
  patientId: string;
  originalFileName: string;
  mimeType: string;
  sizeBytes: number;
  sha256Checksum: string;
  storageUri: string;
  uploadedAt: string;
  uploadedBy: string;
  encryptionStatus: 'AES-256-GCM' | 'Client-Encrypted' | 'Demo-Unencrypted';
}

export interface IDocumentStorageProvider {
  readonly providerType: 'in-memory-demo' | 's3-production' | 'gcs-production';
  store(patientId: string, file: any, uploadedBy?: string): Promise<StoredDocumentMetadata>;
  retrieve(documentId: string): Promise<string | Blob>;
  delete(documentId: string): Promise<void>;
  getMetadata(documentId: string): Promise<StoredDocumentMetadata | null>;
}
```

## 3. Production Security & Envelope Encryption [REQUIRES PRODUCTION BACKEND]

In production:
1. **Server-Side Encryption with Customer-Managed Keys (SSE-KMS)**: Every file written to object storage is encrypted using unique data keys managed by AWS KMS or HashiCorp Vault.
2. **Pre-Signed URLs**: Frontend clients never communicate directly with public storage buckets. Uploads and downloads use time-limited (15-minute) pre-signed URLs generated by the authenticated backend.
3. **Immutability (WORM)**: Clinical documents are configured with Object Lock (Write Once, Read Many) compliance mode to prevent tampering or premature deletion.
